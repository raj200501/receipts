# exprlex token rules

Owner: the language tooling team (tooling@example.invalid). These rules are shared with the
editor plugin and the rule linter, which implement the same tokenizer. Changes go through
the tooling team's review; please do not edit this file in a feature branch.

Version 3. Positions: `offset` counts characters from 0; `line` and `column` count from 1,
and the column counts characters from the start of the line.

## 1. Separators

Spaces, tabs, carriage returns, and line breaks separate tokens and are not tokens. A `#`
starts a comment that runs to the end of the line; the line break itself still ends the
line, so the next line is numbered as usual.

## 2. Numbers

A number is decimal digits with an optional fraction and an optional exponent:

- the fraction is a `.` followed by at least one digit, so `1.5` is one number; the number
  `1.` is the number `1` followed by a `.` token;
- a number may start with the fraction: `.5` is one number;
- the exponent is `e` or `E`, an optional `+` or `-`, and at least one digit: `1e3`,
  `2.5E-4`. An `e` that is not followed by digits is not part of the number;
- the value of a number token is the number the text stands for;
- a number that is directly followed by a letter or an underscore is an error: `invalid number "12a"`, at the first character of the number.

## 3. Strings

A string is written in double quotes or in single quotes, and ends at the same kind of
quote that opened it.

- Between the quotes, a backslash starts an escape: `\n` is a line feed, `\t` a tab,
  `\r` a carriage return, `\\` a backslash, `\"` a double quote, and `\'` a single quote.
  The value of the token has the escapes replaced; its text is the source as written,
  quotes and backslashes included.
- A backslash followed by any other character, or by the end of the input, is an error:
  `unknown escape "\q"`, at the position of the backslash.
- A string that reaches the end of the input or a line break before its closing quote is an
  error: `unterminated string`, at the position of its opening quote. A line break is
  never part of a string.
- A quote of the other kind inside a string is an ordinary character.
- Any other character after a backslash stands for itself: `\q` is the letter `q`, and a
  backslash at the very end of the input is a backslash. Strings never fail on an escape.

## 4. Names and keywords

A name starts with a letter or an underscore and continues with letters, digits, and
underscores. The words `and`, `or`, `not`, `in`, `true`, `false`, and `null` are keywords,
not names, when they are written as a whole word: `android` and `in_stock` are names.
Names are case sensitive (`And` is a name).

## 5. Operators and punctuation

The two-character operators are `**`, `==`, `!=`, `<=`, `>=`, `&&`, and `||`. When two
characters make an operator, they are one token: `a<=b` has the operator `<=`, not `<`
and `=`. The one-character tokens are `+ - * / % < > ! ( ) [ ] , . ? :`.

A single `=` is an error: `unexpected character "="`. Any other character that is not
described here is an error too: `unexpected character "@"`.

## 6. Errors and the end marker

Every error names its place as `at line L, column C`, counted from 1. Tokenizing stops
at the first error. A successful run ends with one `end` token, whose text is empty and
whose position is just after the last character of the input.
